# Tonphueng Connect: LINE OA Web Application

**Status:** approved

**Target:** ต้นแบบตามขอบเขตที่ตกลงสำหรับ PTT Spark Hackathon รอบสมัคร 24 ตุลาคม 2569

**Approval gate:** ผู้ใช้ยืนยัน spec หลัง independent requirements review และอนุมัติ breakdown ของ tickets แล้ว; ก่อน implementation ต้องยืนยันรายการไฟล์ที่จะเขียน ส่วนค่าใช้จ่ายและการเขียนข้อมูลภายนอกยังต้องได้รับอนุญาตเฉพาะ

## Problem Statement

ลูกค้าต้องการค้นหาสินค้าและประสบการณ์ของบ้านต้นผึ้ง เลือกสิ่งที่เหมาะกับตนเอง สั่งซื้อหรือจอง และติดตามรายการผ่านช่องทาง LINE ที่ใช้งานง่าย ผู้ประกอบการชุมชนต้องมีช่องทางจัดการข้อมูลและออเดอร์ของตน ส่วนผู้ดูแลโครงการต้องอนุมัติผู้ประกอบการ กำหนดแพ็กเกจ และเห็นการจองที่เกิดขึ้นจริง

โครงการ “ผึ้งพาเดิน” ต้องมีต้นแบบที่สาธิตการทำงานเชื่อมกันได้ทั้งลูกค้าและหลังบ้านภายใน 24 ตุลาคม 2569 โดยใช้ข้อกำหนดจากสเปกระบบที่ทีมส่งมา ไม่ดึงแนวคิดเก่าหรือภาพประกอบในเอกสารบริบทมาเพิ่มเป็นฟีเจอร์เอง

## Solution

สร้างเว็บแอป Tonphueng Connect ที่เข้าผ่าน LINE OA และ LIFF รองรับ Customer, Staff และ Admin พร้อมข้อมูลสินค้า บริการ แพ็กเกจ Order และ Booking ที่บันทึกและเรียกคืนได้จริง

Customer ดูบริการ ซื้อสินค้าจากร้านเดียวต่อออเดอร์ เลือกรับที่ร้านหรือจัดส่ง จัดแพ็กเกจตามตัวเลือกที่ Admin กำหนด และดู My Trip/My Order ได้ Staff จัดการสินค้าและบริการของตนและรับออเดอร์ ส่วน Admin อนุมัติ Staff จัดการแพ็กเกจ ดูการจอง และเพิ่ม Admin

Chat Assistance สนทนาข้อความอิสระและถามต่อได้ โดยอ้างอิงเฉพาะข้อมูลจริงที่ Staff/Admin เพิ่มไว้ ระบบส่งแชทขอ Feedback ประมาณ 3 วันหลังจบทริปและเก็บคำตอบที่ลูกค้าส่งกลับมา การชำระเงินเป็น QR Payment จำลองที่ระบุชัดเจนว่าไม่มีการรับเงินจริง

คำว่า MVP ในงานนี้หมายถึงต้นแบบครบข้อกำหนดที่ตกลง ไม่ได้หมายถึงการตัดเหลือเฉพาะ Booking: ส่วนซื้อสินค้า หลังบ้าน และแชทอยู่ในขอบเขตด้วย ยกเว้นงานเว็บเล่าเรื่องเดิมที่ผู้ใช้ให้เลื่อนไว้

## User Stories

### Customer และการเข้าสู่ระบบ

1. As a Customer, I want to เปิดเว็บแอปจาก LINE OA และเข้าสู่ระบบด้วยตัวตน LINE โดยไม่กรอกแบบสมัครสมาชิก, so that ฉันเริ่มใช้งานได้สะดวก
2. As a user, I want to เลือก Login Type เป็น Customer, Staff หรือ Admin, so that ฉันเข้าสู่พื้นที่ทำงานที่ตรงกับบทบาทของตน
3. As a Customer, I want to ใช้ Navigation ด้านล่างที่มี Main Page, My Trip และ My Order, so that ฉันกลับไปดูข้อมูลและรายการของตนได้ง่าย
4. As a Customer, I want to เห็นการ์ด Package, Product Order และบริการของเราบน Main Page, so that ฉันเลือกเส้นทางใช้งานที่ต้องการได้

### Package และ Booking

5. As a Customer, I want to ดู Package เป็นการ์ดและเข้าไปดู Sub Package พร้อมราคา, so that ฉันเปรียบเทียบประสบการณ์ก่อนจองได้
6. As a Customer, I want to เห็นรายการประเภท Trail & Running, Wild Fire Study, Cultural Study Trip และช่องทางติดต่อสำหรับ Package เพิ่มเติมตามข้อมูลที่ทีมยืนยัน, so that ฉันค้นหาหรือติดต่อเรื่องประสบการณ์ที่สนใจได้
7. As a Customer, I want to เลือกบริการหรือสถานที่ในแต่ละ slot ของ Sub Package ตามจำนวนที่กำหนด, so that ฉันจัดประสบการณ์ได้ภายในตัวเลือกที่โครงการให้บริการจริง
8. As a Customer, I want to ระบุวันที่ จำนวนผู้เข้าร่วม และรายละเอียดที่จำเป็นของแพ็กเกจ, so that การจองตรงกับความต้องการของฉัน
9. As a Customer, I want to ตรวจตัวเลือก จำนวนคน และยอดรวมก่อนยืนยัน, so that ฉันรู้ว่ากำลังจองอะไรและมีค่าใช้จ่ายเท่าใด
10. As a Customer, I want to ผ่านขั้นตอน QR Payment จำลองที่บอกชัดว่าเป็นการสาธิต, so that ฉันทดลองกระบวนการครบได้โดยไม่โอนเงินจริง
11. As a Customer, I want to เพิ่มสถานที่ทั้งหมดจาก Sub Package เข้า My Trip หลังการชำระเงินจำลองสำเร็จ, so that ฉันกลับมาเปิดดูสถานที่ในทริปได้
12. As a Customer, I want to เปิดข้อมูลทริปและสถานที่ของตนได้อีกหลังออกแล้วกลับเข้าแอป, so that รายการของฉันไม่สูญหายเมื่อปิดหน้าเว็บ

### บริการและ My Trip

13. As a Customer, I want to เลื่อนดูบริการต่อเนื่องโดยไม่มีเลขหน้าและไม่มีดาว Rating, so that ฉันค้นหาบริการได้ตามรูปแบบที่ทีมกำหนด
14. As a Customer, I want to กรองบริการตามประเภทกิจการของ Staff, so that ฉันหาสินค้าชุมชน ที่พัก ร้านอาหาร การท่องเที่ยว/เส้นทางเดินป่า และประเภทอื่นได้
15. As a Customer, I want to เรียงบริการตามระยะจากตำแหน่งของฉันเมื่ออนุญาต GPS, so that ฉันเลือกสถานที่ใกล้ตัวได้
16. As a Customer, I want to เปิดรายละเอียดบริการพร้อม Image Slide และคำอธิบายเต็ม, so that ฉันมีข้อมูลก่อนตัดสินใจ
17. As a Customer, I want to กดหมุดเพื่อเปิดสถานที่ใน Google Maps, so that ฉันนำทางไปยังสถานที่นั้นได้
18. As a Customer, I want to บันทึกสถานที่จากบริการเข้า My Trip ได้เอง, so that ฉันรวมสถานที่ที่สนใจไว้ดูภายหลังได้
19. As a Customer, I want to แยกออกว่ารายการใน My Trip ใดบันทึกเองและรายการใดมี Booking แล้ว, so that ฉันไม่เข้าใจว่าการบันทึกสถานที่เป็นการจอง

### Product และ Order

20. As a Customer, I want to เลือกร้านเฉพาะประเภทสินค้าชุมชนและดู Product List ของร้าน, so that ฉันซื้อสินค้าที่ร้านนั้นเสนอได้
21. As a Customer, I want to เพิ่มสินค้าและจำนวนลงตะกร้าจากร้านเดียวต่อหนึ่ง Order, so that รายการซื้อและผู้รับผิดชอบออเดอร์ชัดเจน
22. As a Customer, I want to เลือกรับที่ร้านหรือจัดส่งตามที่อยู่, so that ฉันเลือกวิธีรับสินค้าที่สะดวกได้
23. As a Customer, I want to เห็นค่าส่งคงที่แยกจากราคาสินค้าและไม่มีค่าส่งเมื่อรับที่ร้าน, so that ฉันตรวจยอดรวมก่อนชำระเงินจำลองได้
24. As a Customer, I want to ชำระ Order ด้วยกระบวนการจำลองและดูรายการใน My Order, so that ฉันทดลองสั่งซื้อและติดตามผลได้ครบ
25. As a Customer, I want to เห็นสถานะ Order และ Tracking Number เมื่อ Staff กรอก, so that ฉันติดตามการเตรียมและส่งสินค้าได้

### Staff

26. As a prospective Staff, I want to สมัครจาก Staff Register โดยระบุชื่อ ที่อยู่ข้อความ พิกัด GPS เบอร์โทร ประเภทกิจการ รูปภาพ อีเมล และรหัสผ่าน, so that ฉันส่งข้อมูลกิจการให้ Admin พิจารณาได้
27. As a prospective Staff, I want to ระบุประเภทอื่นเพิ่มเติมได้และแนบรูปกิจการได้น้อยกว่า 20 รูป, so that ข้อมูลกิจการของฉันตรงตามแบบสมัคร
28. As a prospective Staff, I want to ทราบว่าบัญชียังรออนุมัติและยังใช้สิทธิ์ Staff ไม่ได้, so that ฉันเข้าใจสถานะบัญชีของตน
29. As an approved Staff, I want to เข้าสู่ระบบด้วยอีเมลและรหัสผ่าน, so that ฉันเข้าจัดการกิจการของตนได้
30. As a Staff, I want to จัดการข้อมูลสินค้าและบริการของตน รวมชื่อ รายละเอียด ราคา และรูปสินค้า 1 รูป, so that Customer เห็นข้อมูลที่ฉันเสนอจริง
31. As a Staff, I want to เห็น Order ของร้านตนเป็นรายการงานพร้อมสินค้าย่อย จำนวน รายละเอียด และข้อมูลรับหรือส่งสินค้า, so that ฉันเตรียมออเดอร์ได้ถูกต้อง
32. As a Staff, I want to อัปเดตสถานะกำลังเตรียมของ กำลังไปส่งของ และส่งของเรียบร้อยแล้ว พร้อมกรอก Tracking Number ตามกรณี, so that Customer ติดตามออเดอร์ได้
33. As a Staff, I want to เข้าถึงเฉพาะข้อมูลและ Order ที่อยู่ในความรับผิดชอบของตน, so that ข้อมูลของผู้ประกอบการรายอื่นได้รับการปกป้อง

### Admin

34. As an Admin, I want to เข้าสู่ระบบด้วยอีเมล/รหัสผ่านและตัวตน LINE ที่ผ่านการตรวจและผูกบัญชี, so that สิทธิ์ดูแลโครงการมีการตรวจยืนยันตามสเปก
35. As an Admin, I want to ตรวจข้อมูลและอนุมัติ Staff ที่สมัครเข้ามา, so that ผู้ประกอบการใช้ระบบได้หลังผ่านการพิจารณา
36. As an Admin, I want to กำหนด Package, Sub Package, ราคา และชนิด/จำนวน slot พร้อมตัวเลือกที่มีอยู่, so that Customer เลือกและจองแพ็กเกจได้ตามบริการจริง
37. As an Admin, I want to ดูรายละเอียด Booking ทั้งหมดที่เข้ามา, so that ฉันรับรู้และจัดการข้อมูลการจองของโครงการได้
38. As an Admin, I want to เพิ่มบัญชี Admin ด้วยอีเมลและรหัสผ่านเริ่มต้นตามสเปก, so that โครงการมีผู้ดูแลเพิ่มเติมได้
39. As an invited Admin, I want to เข้าสู่ระบบ ยืนยันรับสิทธิ์ และผูกตัวตน LINE ของตน, so that บัญชี Admin ใหม่พร้อมใช้งานอย่างถูกต้อง

### Chat Assistance และ Feedback

40. As a Customer, I want to พิมพ์คุยกับ Chat Assistance ด้วยข้อความอิสระและถามต่อในบทสนทนาได้, so that ฉันอธิบายความต้องการได้ตามธรรมชาติ
41. As a Customer, I want to ให้ผู้ช่วยถามข้อมูลเพิ่มเมื่อความต้องการยังไม่พอ, so that คำแนะนำตรงกับสิ่งที่ฉันกำลังมองหา
42. As a Customer, I want to ได้คำแนะนำ Product หรือ Package จากข้อมูลจริงที่ Staff/Admin เพิ่มไว้, so that ฉันเลือกสิ่งที่โครงการมีให้บริการจริง
43. As a Customer, I want to ให้ผู้ช่วยบอกเมื่อไม่มีข้อมูลหรือไม่มีรายการที่ตรง แทนการแต่งราคา บริการ หรือความพร้อม, so that ฉันตัดสินใจจากข้อมูลที่เชื่อถือได้
44. As a Customer, I want to เปิดดูสินค้าหรือแพ็กเกจที่ผู้ช่วยแนะนำในเว็บแอป, so that ฉันตรวจรายละเอียดและทำรายการต่อได้
45. As a Customer, I want to ได้รับแชทขอ Feedback ประมาณ 3 วันหลังจบทริปและตอบกลับได้, so that ฉันส่งความคิดเห็นให้โครงการหลังใช้บริการ
46. As a project operator, I want to ให้ระบบบันทึก Feedback ที่ตอบกลับมาและไม่ส่งคำขอเดิมซ้ำเมื่อรันงานตั้งเวลาอีก, so that ความคิดเห็นไม่สูญหายและลูกค้าไม่ถูกรบกวนซ้ำ

### เจ้าของโครงการและการสาธิต

47. As the project owner, I want to ได้รับการสอนตั้งค่า LINE OA, LINE Login, LIFF และ Messaging API ด้วยบัญชีของฉัน, so that ฉันเชื่อมและดูแลระบบเดโมได้
48. As the project owner, I want to สาธิตการทำรายการจนเห็นข้อมูลในหลังบ้านและเปิดกลับมาดูได้จริง, so that ทีมแสดงการทำงานครบกระบวนการในรอบสมัครได้

## Implementation Decisions

### ขอบเขตแอปและเทคโนโลยี

- ใช้ Next.js และ TypeScript เป็นแอปเดียวสำหรับหน้าลูกค้า หน้าหลังบ้าน และ HTTP endpoints ที่ใช้กับ LINE; ไม่แยก backend เป็นอีกโปรเจกต์ในรอบนี้
- ใช้ Supabase PostgreSQL สำหรับข้อมูลจริง ใช้ Storage สำหรับรูปภาพ และใช้ Auth สำหรับอีเมล/รหัสผ่านของ Staff/Admin
- ใช้ LIFF กับ LINE Login สำหรับ Customer ส่วน Messaging API รับแชทและส่งข้อความตอบ/ขอ Feedback; LINE OA และช่องทางที่เกี่ยวข้องใช้ Provider เดียวกัน โดยบัญชีอยู่ภายใต้การดูแลของผู้ใช้ก่อน
- ภาษาในหน้าที่ใช้สาธิตเป็นภาษาไทยและใช้งานจากมือถือผ่าน LINE ได้ ชื่อเมนูหลักสอดคล้องกับสเปกและ glossary
- ยังไม่ล็อก hosting, ผู้ให้บริการ/รุ่นโมเดล AI หรือแผนบริการที่มีค่าใช้จ่าย ขั้นตอนเลือกและตั้งค่าต้องเสนอรายละเอียดและได้รับอนุญาตก่อนเขียนข้อมูลภายนอกหรือเริ่มมีค่าใช้จ่าย

### ตัวตนและสิทธิ์

- Customer ไม่ต้องกรอกอีเมลหรือรหัสผ่านเพื่อสร้างบัญชี ใช้ตัวตน LINE ที่ server ตรวจ token แล้วเป็นตัวอ้างอิงบัญชีและข้อมูลของตน
- Staff ใช้อีเมล/รหัสผ่าน และใช้สิทธิ์จัดการข้อมูลไม่ได้จน Admin อนุมัติ การสมัครไม่สามารถกำหนดสิทธิ์ Admin ให้ตนเองได้
- Admin ใช้อีเมล/รหัสผ่านร่วมกับ LINE ที่ตรวจยืนยันและผูกไว้กับบัญชี เก็บตัวระบุตัวตนที่ตรวจแล้วเพื่อผูกบัญชี ไม่ถือ token ที่หมดอายุเป็นตัวตนถาวร
- การเพิ่ม Admin ต้องผ่าน Admin ที่มีสิทธิ์อยู่ก่อน ผู้ได้รับเชิญต้องยืนยันรับสิทธิ์และผูก LINE ตามสเปก; Admin เริ่มต้นต้องเตรียมผ่านขั้นตอนตั้งค่าที่ควบคุมโดยเจ้าของโครงการ ไม่เปิดช่องให้บุคคลทั่วไปตั้งตนเป็น Admin
- ตรวจสิทธิ์บน server ทุกครั้งที่อ่านหรือเปลี่ยนข้อมูลสำคัญ: Customer เห็นเฉพาะรายการของตน, Staff จัดการกิจการและ Order ของตน, Admin ใช้สิทธิ์ดูแลโครงการตามที่กำหนด
- ค่าบทบาท เจ้าของร้าน เจ้าของ Order และราคาที่ส่งมาจาก browser ไม่ใช่หลักฐานอนุญาตหรือยอดชำระที่เชื่อถือได้ รหัสผ่านและ service credentials ไม่ปรากฏในข้อมูลที่ส่งให้ผู้ใช้

### บริการและข้อมูลผู้ประกอบการ

- หมวดบริการเป็นชุดเดียวกับประเภทกิจการในแบบสมัคร Staff: สินค้าชุมชน, ที่พัก, ร้านอาหาร, การท่องเที่ยว/เส้นทางเดินป่า และอื่น ๆ พร้อมข้อความระบุประเภท
- แบบสมัครเก็บชื่อ ที่อยู่ข้อความ พิกัด เบอร์โทร ประเภท รูปกิจการน้อยกว่า 20 รูป อีเมล และรหัสผ่าน; รูปกิจการกับรูปสินค้า 1 รูปเป็นคนละส่วน
- ข้อมูลบริการต้องเพียงพอสำหรับหน้ารายการ รายละเอียดรูปเลื่อน คำอธิบายเต็ม และหมุด Google Maps ตามสเปก ไม่เพิ่ม Rating หรือหน้ารีวิวบริการ
- ใช้การโหลดรายการต่อเนื่องเมื่อเลื่อนโดยไม่มีเลขหน้า หากใช้ระยะเส้นตรงจากพิกัด ให้แสดงความหมายให้ตรงกับวิธีคำนวณ ไม่แสดงเป็นระยะเดินทางจริง
- ขอใช้ GPS เมื่อต้องเรียงตามระยะ หากลูกค้าไม่อนุญาตหรือหา GPS ไม่ได้ ยังต้องดูและกรองบริการได้ โดยไม่สร้างตำแหน่งสมมติ

### Package, Booking และ My Trip

- รักษาโครงสร้าง Package, Sub Package และ slot ที่ Admin กำหนดชนิด จำนวน ตัวเลือก และราคาได้ตามสเปก ไม่เปลี่ยนเป็นแพ็กเกจตายตัวเพื่อหลีกเลี่ยง requirement เรื่อง slot
- ข้อมูล Package จริง รวมรายการตัวเลือก วิธีคิดราคา วันที่ให้บริการ ระยะเวลาทริป และรายละเอียดเพิ่มเติม ยังรอผู้ใช้อัปเดต ไม่อนุมานจากภาพร่างหรือแบบจำลองการเงิน
- ตรวจตัวเลือก จำนวนผู้เข้าร่วม และราคาอีกครั้งบน server ก่อนสร้าง Booking โดยใช้ข้อมูลที่ Admin บันทึกและสูตรราคาที่ทีมยืนยัน เก็บรายละเอียดที่ใช้ทำรายการไว้ให้เปิด Booking เดิมได้อย่างถูกต้องแม้ข้อมูลปัจจุบันเปลี่ยน
- รายการที่จ่ายเงินจำลองสำเร็จต้องดูได้โดย Admin และ Customer เพิ่มสถานที่ทั้งหมดของ Sub Package เข้า My Trip ได้
- My Trip เป็นชื่อเดียวกับ My List ที่ปรากฏในสเปกเดิม การบันทึกสถานที่โดยตรงไม่สร้าง Booking และไม่ทำให้สถานที่นั้นกลายเป็นการจองที่ยืนยันแล้ว

### Order, ค่าส่ง และการจ่ายเงินจำลอง

- หนึ่งตะกร้าและหนึ่ง Order มีสินค้าจากร้านเดียว ตรวจข้อจำกัดนี้บน server ด้วย การเลือกสินค้าจากร้านอื่นต้องไม่ทำให้เกิด Order รวมหลายร้านโดยเงียบ ๆ
- Order มีรายการสินค้า จำนวน ราคา วิธีรับสินค้า และที่อยู่จัดส่งเมื่อเลือกจัดส่ง ยอดรวมคำนวณจากราคาจริงฝั่ง server โดยแยกยอดสินค้าและค่าส่ง
- รับที่ร้านไม่มีค่าส่ง; จัดส่งคิดค่าส่งคงที่ จำนวนเงินรอผู้ใช้กำหนด ไม่ใช้ราคาจากเอกสารสมมติแทนข้อตกลง
- การชำระทั้ง Booking และ Order เป็นขั้นตอนจำลอง แสดง QR/หน้าจำลองพร้อมคำอธิบายชัดเจน และมีการยืนยันผลสำเร็จจำลอง ไม่มีการสร้างรายการรับเงินจริงหรือกล่าวว่าได้ตรวจยอดจากธนาคาร
- ผลการจ่ายเงินจำลองต้องแยกความหมายจากเงินจริงในข้อมูล การกดยืนยันหรือส่งคำขอซ้ำไม่สร้าง Order/Booking หรือผลการจ่ายเงินสำเร็จซ้ำ
- Staff เห็นสินค้าย่อย จำนวน รายละเอียดและข้อมูลรับ/จัดส่งของ Order ของตน พร้อมอัปเดตสถานะและ Tracking Number ตามสเปก; ไม่บังคับเลขพัสดุสำหรับการรับที่ร้าน

### แชทและ Feedback

- Chat Assistance เป็นบทสนทนา AI แบบข้อความอิสระที่จำบริบทเพื่อถามต่อได้ ใช้ข้อมูล Product/Package/Service จากระบบจริงเป็นฐานคำตอบ
- แนะนำเฉพาะรายการที่มีข้อมูลและพร้อมแสดงต่อลูกค้า แสดงข้อมูลหรือลิงก์ที่ตรวจสอบย้อนกลับไปยังรายการนั้นได้ ไม่ให้โมเดลแต่งชื่อ ราคา วันว่าง หรือเงื่อนไขที่ไม่มีในระบบ
- หากผู้ใช้ยังไม่ระบุความต้องการเพียงพอ ให้ถามต่อ; หากไม่มีข้อมูลที่รองรับ ให้แจ้งตรง ๆ แชทไม่สร้าง Order/Booking หรือยืนยันการจ่ายเงินแทนขั้นตอนที่ลูกค้าต้องทำในเว็บ
- ตรวจสอบ webhook ของ LINE ก่อนประมวลผลและป้องกันการจัดการ event เดิมซ้ำ การส่งข้อมูลบทสนทนาให้บริการ AI ต้องจำกัดไว้เท่าที่จำเป็น ไม่ส่งรหัสผ่านหรือข้อมูลสิทธิ์หลังบ้าน
- ใช้งานตั้งเวลาที่ทำงานได้แม้ผู้ใช้ปิดเว็บ เพื่อค้นหา Booking ที่ถึงเวลาขอ Feedback ประมาณ 3 วันหลังจบทริป ตามเวลา Asia/Bangkok และส่งผ่าน LINE Messaging API
- ใช้วันจบทริปจากข้อมูล Booking/ระยะเวลาแพ็กเกจที่ยืนยัน ไม่ถือวันจองหรือวันจ่ายเงินเป็นวันจบทริป การสาธิตใช้เวลาทดสอบที่ควบคุมได้เพื่อพิสูจน์เงื่อนไขนี้
- บันทึกการขอ Feedback และผลการส่งเพื่อไม่ให้รันซ้ำแล้วส่งซ้ำโดยไม่ตั้งใจ หากส่งไม่ได้ต้องไม่บันทึกเท็จว่าลูกค้าได้รับข้อความแล้ว และต้องแยกผลที่ไม่แน่ชัดจากผลสำเร็จที่ทราบ
- รับคำตอบหลังคำขอ Feedback และเก็บร่วมกับบริบทลูกค้า/Booking ที่ระบุได้ ไม่เพิ่มระบบ Rating, แบบสอบถามหลายส่วน หรือ dashboard วิเคราะห์ Feedback ในรอบนี้

## Testing Decisions

### จุดทดสอบและหลักฐาน

- จุดทดสอบหลักที่ผู้ใช้ยืนยันคือพฤติกรรมผ่านเว็บแอป: ทำรายการในบทบาทหนึ่ง แล้วตรวจผลที่แสดงและบันทึกจริงในบทบาทที่เกี่ยวข้อง ใช้ browser end-to-end tests สำหรับเส้นทางหลัก
- LINE webhook และงานตั้งเวลาเป็นจุดรับข้อมูลภายนอกที่ทดสอบผ่าน HTTP/event และเวลาที่ควบคุมได้ ตรวจผลจากข้อมูลที่เก็บและคำขอส่งข้อความ ไม่ผูกการทดสอบกับโครงสร้างฟังก์ชันภายใน
- ใช้ข้อมูลและบัญชีทดสอบแยกจากข้อมูลลูกค้าจริง สามารถแทน LINE/โมเดล AI/ตัวส่งข้อความด้วย test double ในชุดทดสอบอัตโนมัติเพื่อให้ผลแน่นอน การแทนนี้ไม่ใช่การอนุญาตให้เดโมผลิตภัณฑ์ใช้ mock ในส่วนอื่นนอกจากการจ่ายเงิน
- การตรวจรับ integration ต้องมีการทดสอบ LINE Login, แชท AI และการส่ง Feedback จริงภายหลังอนุญาตตั้งค่าบัญชี/ใช้บริการ/ส่งข้อความ โดยใช้บัญชีทดสอบที่เจ้าของโครงการควบคุม
- ทดสอบเฉพาะพฤติกรรมและขอบเขตที่มีความเสี่ยง เช่น สิทธิ์ ราคา การเก็บข้อมูล webhook ที่ไม่ถูกต้อง และการทำรายการซ้ำ ไม่ทดสอบเพียงว่า implementation เรียกฟังก์ชันตามลำดับเดิม
- Repo ใหม่ยังไม่มีชุดทดสอบหรือ application code ให้ยึดตาม ส่วนเว็บเล่าเรื่องเดิมมีการทดสอบคนละงานและไม่ถูกแก้เพื่อทำร่างนี้ จึงไม่ถือเป็นชุดทดสอบของ Tonphueng Connect
- ระหว่าง implementation ให้ Coder ตรวจ type และรันชุดทดสอบที่ตรงกับ ticket; รันชุดทดสอบทั้งหมดเมื่อจบงาน และใช้ผล review ที่ยังครอบคลุมการเปลี่ยนแปลงล่าสุดโดยไม่ทำซ้ำโดยไม่มีเหตุผล

| AC16 | แชทถามตอบอิสระ ถามต่อ และแนะนำรายการจากฐานข้อมูลที่เปิดดูต่อได้ โดยไม่แต่งราคา/บริการเมื่อไม่มีข้อมูล | ชุดบทสนทนาทดสอบที่มีคำตอบคาดหมายจากฐานข้อมูล และ live smoke test หลังอนุญาต |
| AC17 | webhook ไม่ถูกต้องไม่เปลี่ยนข้อมูล; event เดิมไม่สร้างผลซ้ำ และปัญหา LINE/AI ไม่ถูกแสดงเป็นผลสำเร็จเท็จ | ทดสอบ signature, event ซ้ำ และบริการภายนอกล้มเหลว |
| AC18 | ก่อนถึงกำหนดไม่ส่งคำขอ Feedback; เมื่อถึงประมาณ 3 วันหลังจบทริปจึงส่ง และการรันซ้ำไม่สร้างคำขอเดิมซ้ำ | ควบคุมวัน/เวลาทดสอบ ตรวจบันทึกส่ง และส่งจริงไปบัญชีทดสอบหลังอนุญาต |
| AC19 | คำตอบ Feedback ของลูกค้าถูกเก็บและเชื่อมกับบริบทที่ถูกต้องได้ | อ่านคำตอบกลับจากข้อมูลที่บันทึก ไม่เพิ่มแบบสอบถามหรือ Rating เอง |
| AC20 | เจ้าของโครงการทำตามขั้นตอนตั้งค่า LINE และเปิดใช้เส้นทางหลักกับบัญชีทดสอบของตนได้ | ขั้นตอนที่ตรวจทำจริงและรายการค่าตั้งที่จำเป็น โดยไม่ใส่ secrets ในเอกสารสาธารณะ |

### นิยามว่างานเสร็จ

- พฤติกรรมใน User Stories ทั้งหมดและ AC01-AC20 ผ่านพร้อมหลักฐานที่ตรวจซ้ำได้และไม่มีข้อผิดพลาดสำคัญค้าง โดยอนุมัติ spec และ tickets ก่อน implementation
- ข้อมูลแพ็กเกจ สูตรราคา ระยะเวลาทริป และค่าส่งที่ใช้ตรวจรับได้รับการยืนยันจากผู้ใช้แล้ว ตัวอย่างใน tests ไม่ถูกนำไปอ้างว่าเป็นบริการหรือราคาจริงของชุมชน
- ตรวจ LINE/AI/การส่ง Feedback จริงครบภายใต้บัญชีและการอนุญาตที่ตกลง ไม่ใช้เพียงภาพหน้าจอหรือ mock ผ่านแล้วสรุปว่า integration ทำงานจริง
- มีผล typecheck, การทดสอบพฤติกรรมที่จำเป็น และ code review ตามสเปกและกฎ repo; แก้ข้อผิดพลาดที่กระทบการตรวจรับและตรวจส่วนที่แก้ซ้ำ
- หน้าเว็บเล่าเรื่องเดิมไม่เปลี่ยน ไม่มีการเพิ่มฟีเจอร์จาก archive และไม่มีการอนุมัติ commit/push/deploy หรือค่าใช้จ่ายโดยอ้อมจากการตรวจรับร่างนี้

## Out of Scope

- การแก้เว็บเล่าเรื่องเดิมและการเชื่อม Service List บนเว็บนั้นในรอบนี้ ตามคำสั่งล่าสุดของผู้ใช้ แม้ปรากฏในสเปกต้นทาง
- การรับเงินจริง การเชื่อม payment gateway การตรวจสลิป/ยอดธนาคาร และระบบคืนเงินจริง
- ระบบคำนวณหรือโอนส่วนแบ่งรายได้เข้ากองทุนป่า บัญชี/ERP เต็มระบบ และการรายงานผลกระทบเชิงการเงินที่ไม่ได้กำหนดในสเปกระบบ
- GPS ติดตามคนแบบต่อเนื่อง การรับรองความปลอดภัยหรือสิทธิใช้เส้นทาง และฟีเจอร์คอร์ส/ค่ายจากแนวคิดเก่า; การใช้ GPS ในขอบเขตนี้มีเฉพาะพิกัดกิจการและการเรียงระยะบริการตามสเปก
- ตะกร้าหลายร้าน ค่าส่งตามเส้นทางจริง ระบบสต๊อกหรือพยากรณ์ความต้องการ รีวิว/Rating และระบบจัดการการยกเลิกหรือคืนเงิน ซึ่งยังไม่ได้ร้องขอ
- ให้แชท AI สร้างรายการ ยืนยัน Booking/Order หรือจ่ายเงินแทนลูกค้า และการวิเคราะห์ Feedback ที่เกินการขอและเก็บคำตอบ
- การสร้าง tickets, เขียน application code, commit, push, สร้าง repository ภายนอก, deploy, ส่งข้อความจริง หรือเริ่มใช้บริการเสียเงินในขั้นเขียน spec นี้

### ข้อมูลและการตั้งค่าที่ยังรอ

| รายการ | สิ่งที่ทราบแล้ว | สิ่งที่ต้องได้รับก่อนตรวจรับส่วนที่เกี่ยวข้อง |
| --- | --- | --- |
| Package/Sub Package/slot | ต้องจัดตัวเลือกตาม slot และ Admin กำหนดได้; ผู้ใช้จะอัปเดตรายละเอียด | รายการที่เปิดให้จอง ตัวเลือก จำนวน slot วิธีคิดราคา ระยะเวลาทริป วันให้บริการ และรายละเอียดที่ต้องกรอก |
| ค่าส่ง | คงที่ แยกจากราคาสินค้า; รับที่ร้านไม่คิดค่าส่ง | จำนวนเงินบาทที่ผู้ใช้อนุมัติและขอบเขตที่ใช้ค่านั้น |
| สินค้าและบริการ | Staff/Admin เป็นแหล่งข้อมูลจริง | ชื่อ รายละเอียด ราคา รูป พิกัด ข้อมูลติดต่อ และชุดข้อมูลที่อนุญาตให้ใช้สาธิต |
| LINE | ผู้ใช้เป็นเจ้าของบัญชีก่อนและต้องได้รับการสอน; ยังไม่ได้ตั้งค่า | OA/Provider/LINE Login/LIFF/Messaging API บัญชีทดสอบ ค่าตั้ง และ HTTPS endpoint ที่อนุมัติ |
| บัญชีเริ่มต้น | มี Admin เริ่มต้นและ Staff ที่สมัครรออนุมัติ | ข้อมูลบัญชีทดสอบที่เจ้าของโครงการควบคุมและขั้นตอนตั้งค่าโดยไม่เผยรหัสผ่าน |
| AI | สนทนาอิสระ ถามต่อ และอ้างข้อมูลจริงเท่านั้น | ผู้ให้บริการ/รุ่นโมเดล บัญชี API วิธีเก็บ key และวงเงินที่อนุมัติก่อนเรียกจริง |
| งานตั้งเวลา/hosting | ทำงานได้แม้ลูกค้าปิดเว็บ ขอ Feedback ประมาณ 3 วันหลังจบทริป | บริการที่เลือก วิธีรันตามเวลา และสิทธิ์ตั้งค่า/deploy; ไม่ถือว่ามีเครื่องหรือบัญชีบริการพร้อมแล้ว |

ข้อมูลเหล่านี้เป็นเงื่อนไขเตรียมการและตรวจรับ ไม่ใช่เหตุให้ลบ requirement ออกจากงาน หรือให้แต่งข้อมูลแทนผู้ใช้ รายการที่ยังไม่พร้อมต้องรายงานว่า pending ไม่รายงานว่าฟีเจอร์ผ่านการตรวจรับครบแล้ว

### ลำดับการอนุมัติถัดไป

1. ผู้ใช้ตรวจและยืนยัน spec นี้ หรือขอแก้เฉพาะประเด็นที่ยังไม่ตรง
2. ใช้ `to-tickets` เสนอส่วนงานที่สาธิตได้และ blocking edges พร้อมรายชื่อไฟล์ ticket แล้วรอยืนยันก่อนเขียน
3. ทำทีละ ticket ตามขอบเขตและพฤติกรรมที่ยืนยัน พร้อมตรวจเฉพาะส่วนที่เกี่ยวข้อง
4. ทำ code review ตามสเปกและกฎ repo โดยใช้ผล review จาก implementation ถ้าครอบคลุมแล้ว; ไม่เริ่ม commit/push/deploy หรือเขียนข้อมูลภายนอกจนกว่าจะมีการอนุญาตเฉพาะ
