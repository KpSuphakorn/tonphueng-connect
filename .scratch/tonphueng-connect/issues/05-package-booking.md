# 05: จอง -> จ่ายจำลอง -> Admin เห็น -> เข้า My Trip

**What to build:** Customer ระบุวันและจำนวนคน ยืนยันแพ็กเกจด้วยการจ่ายเงินจำลอง Admin เห็น Booking จริง และ Customer เพิ่มสถานที่ในแพ็กเกจเข้า My Trip ได้

**Blocked by:** 04: Admin จัดแพ็กเกจ -> Customer เลือก slot.

**Status:** ready-for-agent

**Spec:** [Approved spec](../spec.md)

**Coverage:** User Stories 8-12, 37; AC09, ส่วน Booking ของ AC10 และ AC14-AC15

## Acceptance criteria

- [ ] Customer ระบุวัน จำนวนผู้เข้าร่วม และรายละเอียดจำเป็นตามแพ็กเกจ พร้อมตรวจตัวเลือกและยอดรวมก่อนยืนยันได้
- [ ] Server ตรวจตัวเลือก จำนวนคน และคำนวณจากราคาหรือสูตรที่ยืนยัน ไม่เชื่อยอดที่ browser ส่งมา
- [ ] ขั้นตอน QR Payment ระบุชัดว่าเป็นการจำลอง ไม่เรียกเก็บเงินจริงหรือกล่าวว่าตรวจยอดกับธนาคารแล้ว
- [ ] ยืนยันจ่ายจำลองแล้วบันทึก Booking เดียวที่มีเจ้าของ รายละเอียด ราคา และผลจำลองชัดเจน; คำขอซ้ำไม่สร้างรายการซ้ำ
- [ ] Admin เห็นรายละเอียด Booking ที่เข้ามา Customer เปิดข้อมูลของตนหลังเข้าใหม่ได้ และบัญชีอื่นอ่านหรือแก้รายการนั้นไม่ได้
- [ ] หลังจ่ายจำลองสำเร็จ Customer เพิ่มสถานที่ทั้งหมดของ Sub Package เข้า My Trip ได้ และแยกจากสถานที่ที่บันทึกเอง
- [ ] เก็บรายละเอียดการจองและข้อมูลวันจบทริปตามข้อมูลแพ็กเกจที่ยืนยัน เพื่ออ่านรายการเดิมและใช้ขอ Feedback ได้ถูกต้อง
- [ ] ผ่านการทดสอบเลือก -> ตรวจราคา -> จ่ายจำลอง -> Admin เห็น -> My Trip รวมแก้ราคา/เจ้าของและส่งคำขอซ้ำ

## External prerequisites and evidence

- ตรวจรับด้วยสูตรราคา วันที่ให้บริการ ระยะเวลา และรายละเอียดเดโมตามนโยบาย prototype ใน spec ได้ ไม่ใช้วันจองหรือวันจ่ายแทนวันจบทริป
- ข้อมูลธุรกิจจริงไม่เป็น blocker ของต้นแบบ แต่ integration ที่จำเป็นของงานหลักยังต้องตรวจรับจริง; ไม่ต้องรอ optional Tickets 09–10
